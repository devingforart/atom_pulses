# Website language and appearance

The React website supports `es`, `en` and `pt-BR`. Product content, account,
authentication, recovery, legal pages, public exhibitions and Cloud controls use
the same catalog at `frontend/src/locales/messages.json`.

`frontend/src/i18n.tsx` supplies reactive subscriptions, interpolation and
preferences. Spanish source strings are stable catalog keys; English and
Brazilian Portuguese must preserve their placeholders. This is application-level
localization, not DOM text replacement or a page translation service.

First visit: a supported browser language wins, then a recognized time zone
provides a geographic fallback; otherwise English. Time zone alone is not a
reliable indication of a person's language. Manual choice is stored as
`pulso-language`. HTML language and page title update without reloading.
Date and number formatting use the selected locale; time display uses the
visitor's actual device time zone. Currency codes and prices are not converted.

Appearance defaults to `prefers-color-scheme`, responds to live device changes,
and offers explicit dark/light overrides plus a System option. The existing
`pulso-studio-theme` preference is retained. The same choice applies to marketing
pages and Cloud. Browser storage restrictions do not prevent use of the app.

User prompts, composition titles, musical content, exported note data and API
enum values are not translated. Changing language does not remount the studio,
change a generation request, clear its draft or restart audio. Backend/provider
diagnostics not found in the catalog remain intact rather than being silently
rewritten. AI responses, transactional email templates and Stripe-hosted pages
are separate content surfaces, not automatically translated by this UI module.

Tests: `npm test --prefix web/frontend`; build: `npm run build --prefix web/frontend`.
Catalog tests check nonempty translations and matching interpolation parameters.
Browser QA also checks all three locales, live system appearance, preserved
drafts and responsive layout with mocked account data and existing MIDI files.

The standalone development studio under `local-studio/` is a separate frontend;
this localization applies to the public React website, not the VST or local
laboratory controls.
