# Whole-work foreground first — local opt-in

Positive anchor remains 92b8f02. Local flag PULSO_AI_CLUB_MELODY_FIRST=1
changes actual scheduling, not just wording. Existing mode is unchanged without
the flag. Cloud is not modified or deployed.

Pass one writes every technical window for the protagonist and all owners named
in musical_arcs, jointly where possible. Only after the entire foreground is
accepted does pass two write all remaining owners against that immutable score.
The cast, harmony, nucleus and intended Club meter are still planning context.
No MIDI is copied, filled or generated by scheduling code. Normal limited AI
revisions run after the ensemble is complete and may revise foreground as before.

The plan carries score_writing_order=foreground_first_v1. Completed checkpoint
units count pass-windows, so recovery resumes that order even if the environment
flag changes. Old checkpoints keep their original single ensemble-window order.
Solo/no-separable-foreground plans fall back to existing scheduling. Empty
AI-planned spans remain silent and do not make paid writing calls.

Tradeoff: two writing passes can increase API calls/time. This experiment tests
musical priority, not latency. The user will compare a fresh 180-second Club etude
with the same seed and options. Partial MIDI during pass one is intentionally
unaccompanied and must not be judged as the final mix. Native tests cover owner
partition, legacy ordering, marker and solo fallback; source regression checks
cover pass-before-section ordering and checkpoint count. Listening remains needed.
